# 架构与代码导航

## 请求流程

1. FastAPI校验身份、会话属主、CSRF/Origin与请求幂等。
2. Router在DIRECT、SINGLE、MULTI、AGENT、REFUSE之间选择路径。MULTI是多方面政策检索，不等同于多个专业Agent。
3. 政策路径复用有界执行器；启用LangGraph/Supervisor后，业务路径按结构化任务调度专业节点。
4. 工具在实际读取边界核验owner与能力。模型输出不能授予权限。
5. 候选经过Schema、来源和语义检查，由应用统一保存消息、Run终态和事件。
6. SSE发送持久事件，重连只回放。未知外部结果不自动重放执行。

## 状态边界

Run是应用执行，Checkpoint是图状态，Pending Action是待确认操作。订单、退货和退款另有业务状态。节点COMPLETED不保证交付，Run成功不保证任务正确，退款申请不等于批准或到账。

图适配器复用应用持久化，不再创建另一套消息与终态。事件和Trace保留必要诊断，凭据与隐藏推理不进入用户投影。

## 扩展原则

工具应定义输入输出、来源与权限，复用仓储。跨域任务传递结构化事实和引用。新增能力同时测试应调用与不应调用的场景。

政策检索默认BM25，多方面路径可使用向量、融合与重排。知识版本、索引指纹与有效时点需要一致。检索失败、无记录和证据不足分别处理，不返回同一个成功空结果。

历史三跳Self-RAG保留用于回放，不是当前默认在线回退。存在实现不等于默认启用。
