# 数据集、指标、消融与放行口径

状态：评测协议，不是项目成绩。第一次冻结测试集前允许修订，但每次修订须提交版本、原因及样本迁移清单；冻结后发现标注错误时保留旧/新结果。所有原始运行记录只追加，派生报告可由固定脚本幂等重建。

## 数据集与标注

初始规模：意图/路由约 100 条，政策检索 80–120 条（其中至少 25 条复合政策），端到端任务 40–60 条，另有 15 工具逐项契约测试和故障注入集。按**业务场景、政策组合和问题模板**分组，再以组为单位划分开发/验证/冻结测试，避免只换订单号的近重复泄漏。冻结测试集不可用于提示词、词典或路由规则调参。所有问题注明来源（人工编写/真实脱敏/模型生成后人工校订）；模型生成样本不能直接当金标。

每条样本至少包含 `case_id,group_id,dataset_split,user_query,user_id,session_history,order_snapshot_id,knowledge_version,expected_intent,expected_strategy,required_conditions,acceptable_evidence_ids,expected_tool_calls,expected_business_effect,critical_facts,scoreability,annotator,review_status`。一人项目至少先标注后隔天盲审；难例保留两个可接受答案或 `unscorable_reason`，不可评分样本单列，不从分母里悄悄删掉。政策金标允许多个等价条款，但不能把泛化 FAQ 与具体专题条款混为唯一正确 ID。

**阶段适用范围：** “先标注后隔天盲审”是将 `test_candidate` 正式冻结并开始冻结集评分的前置条件。它不是 M1 API/会话开发的前置门槛。M0 可在经人工审核的 dev/validation 样本上进行预备评测并如实报告分母；这不构成冻结集成绩，也不能用于提前调参 test_candidate。隔日盲审须记录真实审核者与时间；样本有分歧时先按版本化审核流程裁决，不得直接冻结。

## 指标定义

| 层 | 计算方式 | 附加记录 |
|---|---|---|
| 路由 | 各类 precision/recall/F1 与宏 F1；五类混淆矩阵 | `AGENT+SINGLE/MULTI` 内部策略也单列 |
| 检索 | P@1、Recall@3/5、MRR；必要条件覆盖率 = 有有效证据的必需条件数 / 必需条件数 | 按单跳、二跳、三跳与文档类别分组 |
| 证据与答案 | 有效引用率 = 引用到本轮有效证据的结论数/带引用结论数；关键事实正确率 = 正确关键事实数/可评分关键事实数 | 不支持结论数、缺证据转人工率、模型裁判与人工不一致数 |
| 工具与业务 | 工具成功数/合法尝试数；任务成功 = 期望事实与预期数据库副作用全部满足 | 错误工具调用、未确认写入、跨用户读取、重复写入 |
| 可靠性 | P50/P95 节点及总耗时；超时/降级/未知结果率；恢复成功率 | 统计样本量、运行环境、首次模型加载是否计入 |
| 成本 | 每轮输入/输出 Token、模型请求数、Embedding/精排耗时和按价格快照估算的 USD | 成功、失败、未知调用分别计数；不可得的 usage 记 unknown |
| 记忆 | 关键事实保持率、最新纠正生效率、长会话任务成功率、Token 节省率 | 30/80 轮及三阈值用例 |

比例指标提供原始分子/分母与 Wilson 95% 区间；同一测试集上的方法差异用配对 bootstrap 给区间，并逐条展示得失案例。小样本不宣称统计显著或泛化性能。人工复核冻结集关键政策结论和业务副作用；LLM-as-Judge 只辅助，不能单独证实“零幻觉”。

## 必做对照与消融

1. 路由：规则、纯 DeepSeek、DeepSeek+规则兜底；同一冻结集，记录调用成本。
2. 检索：BM25、稠密、RRF、RRF+Cross-Encoder；模型权重、文档和 top-k 固定。RRF 不优于最强单路时照实报告。
3. Adaptive 深度：固定单跳、最多二跳、最多三跳、自适应提前停止；比较全条件覆盖、正确率、延迟与 Token。
4. 编排：单 Agent 与多 Agent 使用同一 DeepSeek 模型、同一 15 工具可访问集合、同一知识库和订单快照；比较跨域任务成功与成本。
5. 忠实度：原始生成、引用/事实规则校验、规则+一次重写；区分漏报与新引入错误。
6. 记忆：无压缩、Soft、Hard、Auto；在相同长会话序列中比较事实保持与成本。
7. MCP：本地工具与 MCP 适配后的同业务工具对照参数/结果一致性、失败可观测性和额外延迟；协议兼容不是“模型效果提升”。

### M2-R 在线检索/回答协议补充（2026-10-20）

用户已批准将当前三跳 Self-RAG 移出在线 SINGLE/MULTI 主链路。M2-R 用已批准 dev/validation 上的 BM25 与 `HYBRID_RERANK`（BGE-small + BM25/RRF + bge-reranker-base）进行配对检索比较；48 条既有结果只有在数据哈希、模型 revision、语料、参数与评价口径一致时才可复用，否则重跑对应的 dev/validation 检索项。不得读取/调参 `test_candidate`。

线上 MULTI 的质量记录按每个样本统计：所需政策方面是否被识别、方面证据覆盖、有效时间/版本、引用属于本轮检索、核心条件覆盖、无依据确定性结论、适当澄清、请求数、Token、费用估算及端到端延迟。BM25 无候选的有界增强尝试与 MULTI 多方面增强必须单独记录触发率、增益、误触发和降级。非政策事实须有对应业务工具结果；LLM Judge 仅辅助，不替代程序化证据约束或人工裁决。

M2-R 工程测试验证当前有界策略（BM25 默认、有限 HYBRID_RERANK、单次答案生成、预算、引用/时效、两种编排/持久化兼容），不再要求当前线上路径运行或通过三跳 Self-RAG。历史三跳四类边界仍保留旧实现的回归证据，不用来判定新路径正确，也不因新路径退出而删除。M2-R 质量门槛沿用既有正式阈值和硬安全条件；本轮 dev/validation 真实结果是受控工程/质量诊断，人工批准、隔日盲审、冻结测试和 M6 结果仍按原分母与流程，不自动放行。

## 放行规则与目标

**硬门槛（自动判定）**：身份攻击集全部拒绝；退款/退货/取消的未确认、过期、跨用户写入均为 0；同一订单不同原因并发整单退款至多一个开放申请，取消与退款并发满足金额约束；重复与并发确认至多产生一次业务写入；15/15 工具契约正常与异常用例通过；MCP 两种传输的发现、调用、断线、未授权用例通过，受控 MCP 写工具在伪只读声明下仍须本地确认且只写一次；**当前启用的在线检索策略须满足证据来源、版本/时效、引用和故障降级边界；历史三跳 Self-RAG 的旧回归记录不构成 M2-R 在线门槛**；政策变更前后按明确生效时点选对版本；Soft/Hard/Auto 在长会话中确实触发并在后续轮次使用摘要；SSE 断线后可查询持久化最终状态。任何适用硬门槛失败即未完成交付。

**初始质量目标（非虚构成绩，M0 用基线校准并记录变更）**：冻结集路由宏 F1 ≥0.85，政策必要证据 Recall@5 ≥0.85，人工复核关键事实正确率 ≥0.90。若未达，系统功能是否完整与算法收益分别报告，不能通过改金标或只展示成功案例“达标”。不把“相对基线提升 10%”作为硬交付条件；负结果也应附失败归因、延迟和成本。

## 报告与重现

每次运行生成不可变 `run_id`，记录配置哈希、Git commit、知识库/订单快照、数据集版本、模型名/revision、提示词版本、权重、top-k、RRF 参数、预算、实际调用、原始响应与价格访问日期。汇总脚本读取指定 `run_id`，输出指标表、区间、分组错误、失败案例及与基线的配对差异。不可评分、依赖故障、模型拒答和结果未知均有显式分类，不丢弃异常样本。
